Eligibility and limits:
Join build remains serial; eligible single-join probing shares immutable build columns/index.
Parallel full-sort collection and owned gathering remain serial. Primary string merge prefixes are optional.
Standalone DISTINCT, a single global DISTINCT aggregate, and DISTINCT followed by terminal ordinary aggregates parallelize.
Multiple/grouped DISTINCT aggregates, multiple joins, and join-to-TopN parallel pipelines retain serial fallback.
Runtime Parquet filters prune unopened row groups for proven direct signed integer TopN/inner/semi bounds.
The ordinary balanced fixture overlaps statistics; use dedicated pruning counters, not Top50 timings, to assess avoided work.

Memory and methodology:
Join output uses bounded candidate batches (up to 1024 rows); the parent scope includes nested retained build allocations.
Sort scratch remains 8 bytes/row; optional string caches cost at most 16 bytes/row during each phase and release before gathering.
Requested bytes, Go heap allocation, retained slab capacity, and process memory are distinct.
No Linux process footprint or native arm64 timing claim. Cross-compilation is compilation only.
Desktop timing variability is visible in raw ranges and per-round medians; no universal or cross-machine claim.
Full 37-query cross-engine smoke uses one sample for correctness, not ranking.
Raw commands, source/fixture/binary hashes, all samples and allocator snapshots are in paired.json.
Microbenchmarks are stage-oriented worker comparisons, not a frozen before/after engine comparison.
